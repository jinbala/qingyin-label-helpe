# 更新记录

## v1.4.8 · 2026-10-21

渲染与存储路径的性能、稳健性维护。界面流程与打印输出保持不变。

### 性能

- 保存模板时不再对整个模板库做两次 JSON 序列化：未改动的模板按对象引用直接跳过比较，嵌入图片不再被反复字符串化。
- 设计器编辑期只做结构校验，嵌入图片的完整格式校验移到保存与导入时；拖动、对齐、方向键微调不再对整段图片数据跑正则。
- 普通本地模板每条标签的条码只编码一次。原先用于测量尺寸的那次完整渲染，实际只读取了两个固定常量（700 × 185）。
- 生成 PDF 改为按时间片让出主线程（累计超过 8 ms 才让出一次），不再每个标签触发一次计时器往返。
- 循环内的位置设置归一化提到循环外；勾选多行时表头列索引只解析一次。

### 修复

- 本地文字模板补齐变量：`{{labelCode}}` 与 `{{origin}}` 此前在 `qingyin-template/v1` 中会被静默替换为空字符串，与 `docs/usage.md` 的说明不一致。现在两类模板使用同一套变量。
- 模板总量超过浏览器为扩展保留的 10 MB 时，在写入前拒绝并指出占用最大的模板，不再等到浏览器返回难以理解的配额错误。
- PDF 体积上限由 24 MB 调整为 12 MB，避免消息通道序列化时出现上百 MB 的临时字符串；提示改为引导减少数量或降低分辨率。
- 生成张数上限改为在累加每一批之前判断，不会先超出再报错。
- 打印明细已为空时，店号输入框不再重复清空与重绘。
- 扩展重新加载或更新后，已打开的商家页面仍在使用旧内容脚本，此时点击“生成 PDF”只会显示原始英文错误 `Extension context invalidated.`。现在改为提示“扩展已重新加载、更新或后台未响应，请刷新本页面（F5）后重试”，页面内的更新提示也补充了刷新商家后台页面这一步。

### 工程

- 构建不再依赖外部 Python：改用 Node 自带的 zlib 写入 ZIP，并按中央目录回读校验每个条目的长度与 CRC。产物在任意装有 Node 的环境（含 Linux CI）都能生成，且时间戳固定、可重复。
- 新增根 `package.json`（`check` / `test` / `coverage` / `build` / `format`）、Prettier 与 EditorConfig 配置、GitHub Actions 工作流。
- 格式化 `src/**/*.css`：`style.css` 由单行 5 795 字符变为常规缩进，可读可 diff；构建不做 CSS 压缩，格式不影响产物体积。
- 声明 `minimum_chrome_version: 111`。扩展使用 `world: "MAIN"` 注入页面脚本，低于该版本的 Chrome 会静默跳过。
- 合并重复实现：卖家后台域名判定统一到 `src/integration/origins.mjs`，换行算法统一到 `src/printing/text-fit.mjs`，变量替换统一使用 `src/core/design.mjs`。`background.mjs` 中原先重复两遍的域名正则已删除。

### 验证

- 本地 58 项自动化测试全部通过（新增 base64 分块往返、存储配额拦截两项）；`node scripts/build.mjs` 通过，打包 49 个文件并逐个回读校验。真实 TEMU 页面、打印机与 600 DPI 输出仍需现场复核。

## v1.4.7 · 2026-10-21

### 功能

- 多个发货批次一起打印时，在打印明细上方显示“不同发货批次之间添加提示页”选项，由用户决定是否插入区分页；只有一个批次或非发货页数据时隐藏该选项。
- 取数按勾选的发货批次分组请求，每条商品记录带上批次序号，批次边界不再依赖相邻 SKU 是否相同判断。同批次内不会重复插入，批次边界同时也满足 SKU 不同时只插入一张。
- 提示页改为截图样式：按所选模板纸张生成外边框、上下两条黑色粗条，中间居中显示“前后规格不同，请不要贴错”；可视化模板与本地文字模板共用该提示页。

### 验证

- 新增批次提示页数量、批次分组取数、提示页像素样式和界面选项的测试；本地 56 项自动化测试全部通过。真实 TEMU 页面与打印机仍需现场复核。

## v1.4.6 · 2026-10-21

### 修复

- 发货单页勾选“发货批次”后只打印一条：发货批次与物流信息列使用跨行单元格，同一批次下其余发货单行没有独立勾选框。旧实现每个勾选行只取一个编号，导致整批只查询、生成一张发货单的标签。

- “勾选顺序”排序对同一批次内取出的多个发货单号一并记录。

### 验证

- 新增发货批次跨行勾选的 DOM 测试；本地 52 项自动化测试全部通过。真实 TEMU 页面与打印机仍需现场复核。

## v1.4.5 · 2026-10-18

本次合并 v1.4.4 的预览清晰度调整和 v1.4.5 的模板备份功能。

### 功能与修复

- 大图预览根据显示区域和屏幕像素密度生成高清图像，保留小字抗锯齿边缘。816 像素显示宽度的本地示例由 496 像素提高到 1257 像素；实际分辨率随窗口变化。
- 普通本地模板的条码矢量按纸张像素网格直接渲染，避免先生成低分辨率位图再放大；移动编号不改变条码线条的采样位置。
- 新增“备份全部模板”和“导入备份”，迁移模板、嵌入图片及已保存的位置。相同编号、内容和位置的模板跳过，编号冲突另存副本；导入失败保留现有模板。
- 备份读取其他页面刚保存的数据，同时保持当前页面的保存差异基线，防止随后保存时误删其他页面的新模板。
- 增加覆盖原目录后重新加载的更新说明。卸载扩展可能清除浏览器存储，旧代码文件夹不是数据备份；本次没有恢复已被卸载删除的用户模板。

### 性能与输出

- 保留底图缓存，连续拖动只更新定位提示，松手后更新图像。
- 窗口和屏幕密度变化合并更新，避免画布尺寸变化触发循环重绘。
- 预览最长边限制为 3200 像素，总像素预算约 400 万；屏幕灰度预览与打印分辨率独立，PDF 仍为所选 300/600 DPI 的黑白输出。

### 文档与发布状态

- 增加 Chrome 商店介绍、权限与数据用途说明、审核步骤、隐私政策草稿，以及生成图标和宣传图的准备脚本。
- 发布者信息为空，隐私政策未公开托管，真实界面截图未补齐。商店发布已按用户要求暂停，没有注册开发者账号、产生注册费用或提交审核。

### 验证与隐私

- 51 项本地自动化测试覆盖高清预览、连续拖动、窗口变化、跨存储备份迁移、编号冲突、失败重试、模板持久化及 PDF 尺寸等行为。
- 构建校验包含脚本语法、间接模块资源访问、第三方库校验值、域名权限与独立性检查。
- 真实 Chrome、真实账号、实物打印机及双扩展同时启用仍未完成系统验收；模拟环境结果不代表现场性能。
- 本次提交只包含轻印代码、测试和文档；原插件、参考归档、依赖安装目录、生成包及生成的截图/PDF 不纳入 Git。第三方开源库许可证继续保留。
